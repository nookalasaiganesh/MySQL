Transaction
--> The process of combining all related operations into a single unit and executing then according to the rule "Either all operators should succeed or none should be succeed" 
--> A transaction is considered as a single unit of work and follows the principle "Either all or none"

Example: FUNDS TRANSFER
consider a money transfer process between two accounts:
Debit amount from the sender's account
credit amount into the receiver's account
Both operations should be executed as a single transaction
If the amount is debited from the sender's account successfully, but crediting the receiver's account fails, it may lead to data inconsistency problems

Types of transaction:
1.Local transaction
2.Global transaction

1.Local Transaction
--> In local transactions all operations of a transaction are executed on the same database
Example:
Funds transfer from one account to another account where both accounts belong to the same bank

2.Global Transaction
-->In global transactions all operations of a transaction are executed on the different database
Example:
Funds transfer from one account to another account where both accounts belong to the different bank

ACID properties:
A-atomicity
--> ALL or NOTHING
C-consistency
--> The database remains in a valid state 
I-isolation
--> Transactions do not interface with each other
D-durability
--> committed changes are permanent

TCL-Transaction Control Language 
1.COMMIT
--> It is used to permanently save all changes made during the current transaction into the database
--> Once committed:
   1. Changes become permanent
   2. Other users can see the changes
   3. You cannot undo the changes using rollback 
2.ROLLBACK
--> It is used to undo all changes made in the current transaction before a commit 
--> If something goes wrong rollback restores the database to its previous state
3.SAVEPOINT

Introduction to Stored procedures
--> A stored procedure is a named, precompiled collection of one or more SQL statements that is stored inside the database and can be executed called whenever required. Instead of sending long block of SQL from an application every time, the application simply calls the procedure by name

use of stored procedures:
1.performance
2.reusability
3.security
4.reduced network traffic
5.maintainability
6.consistency

Advantages:
1.Faster execution after completion
2.Reduced duplicate SQL
3.Supports transaction, loops, conditions, variables, etc.,
4.Easy maintenance

Disadvantages:
1.Debugging can be difficult
2.Vendor specific syntax
3.Complex procedures may become hard to maintain

Syntax:
DELIMITER //
CREATE PROCEDURE procedure_name()
BEGIN
 --- sql statements
END //
DELIMITER

IN parameter
--> An IN parameter is used to pass a value into a stored procedure 
--> The procedure can use the value, but changes made to the parameter inside the procedure are not returned to the caller

Syntax:
CREATE PROCEDURE procedure_name(IN parameter_name datatype)
BEGIN
    sql statements
END;
DELIMITER;
